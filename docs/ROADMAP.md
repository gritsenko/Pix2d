# Pix2D — Long-Term Roadmap

> **Status:** Draft proposal · Last updated: 2026-07-13 · Baseline version: [v3.9.0](https://github.com/gritsenko/Pix2d/releases/tag/v3.9.0)
>
> This document is written for **both humans and AI coding agents**. Each work item includes context, acceptance criteria hints, and reference links so an agent can pick up a task with minimal extra briefing. Read [`CLAUDE.md`](../CLAUDE.md) and [`CONTRIBUTING.md`](../CONTRIBUTING.md) before starting any task. UI work must follow the project skill at [`.claude/skills/pix2d-ui`](../.claude/skills/pix2d-ui).

## 1. Vision & Positioning

**Pix2D is the asset pipeline tool for indie game developers: a modern, free, open-source sprite/pixel-art/animation editor that runs everywhere — Windows, Linux, macOS, Android, and the browser.**

Litmus test for every roadmap item:

> *Does this get an artist's asset into a running game faster?*

### Competitive landscape (for context, not imitation)

| Competitor | Strengths | Our differentiation |
|---|---|---|
| [Aseprite](https://www.aseprite.org/) ([source](https://github.com/aseprite/aseprite)) | Industry standard, huge feature set, scripting | Paid, desktop-only, dated UI. We win on: free/MIT, mobile + web, modern UI |
| [Pixelorama](https://orama-interactive.itch.io/pixelorama) ([source](https://github.com/Orama-Interactive/Pixelorama)) | Free, Godot-based, active community | We win on: native performance (SkiaSharp), mobile UX, stylus/pressure support |
| [Piskel](https://www.piskelapp.com/) | Zero-friction web editor | Effectively unmaintained. We win on: everything, once our web version is first-class |
| [LibreSprite](https://libresprite.github.io/) | Free Aseprite fork | Slow development. We win on: velocity, modern stack |

### Strategy in the AI era (2026)

Two real threats: (a) casual users generating assets instead of drawing them, (b) AI-native competitor editors. Two real advantages: (a) generative models are still bad at strict-palette, grid-consistent, animation-consistent pixel art — manual control remains technically necessary in this genre; (b) a solo maintainer with AI agents now matches the output of a small team, while competitors carry legacy codebases.

**Positioning answer:** Pix2D does not compete with generation — it *hosts* it. "AI drafts, human finishes, agent exports." And Pix2D itself becomes a tool that agents can drive (CLI + MCP), making it a node in AI game-dev pipelines rather than a victim of them. See [Track E](#track-e--ai--agent-integration).

## 2. How to read this roadmap (for agents)

- Work is organized into **Horizons** (time-ordered) and **Tracks** (thematic, continuous).
- Priority: `P0` = drop everything, `P1` = next release, `P2` = planned, `P3` = opportunistic.
- Before implementing: check [open issues](https://github.com/gritsenko/Pix2d/issues) for duplicates; link the roadmap item in the PR description.
- Definition of done for any item: code + tests (see [Track Q](#track-q--quality-infrastructure)) + entry in release notes draft + no regression in golden-image tests.
- Tech stack anchors: [Avalonia UI](https://docs.avaloniaui.net/) (currently 12.0.5), [Avalonia.Markup.Declarative](https://github.com/AvaloniaUI/Avalonia.Markup.Declarative), [SkiaSharp](https://github.com/mono/SkiaSharp) (currently 3.119.4), [SixLabors.ImageSharp](https://github.com/SixLabors/ImageSharp), .NET / C#. Web build runs on the Avalonia [WebAssembly backend](https://docs.avaloniaui.net/docs/guides/platforms/how-to-use-web-assembly).

## 3. Horizon 1 — Stabilization & Trust (0–3 months)

Goal: after the large v3.8.0 release, make export/selection/drawing bulletproof. Ship as a series of `3.8.x` patch releases.

### H1.1 Bug burn-down `P0`
- [x] Onion-skin layer leaks into export — [#230](https://github.com/gritsenko/Pix2d/issues/230). `Pix2dSprite.Layer.OnDraw` now gates the previous-frame ghost on `vp.Settings.RenderAdorners` (true only for the interactive editor viewport; false for every export/preview/thumbnail/clipboard/project-pack render), matching the existing `EditMode`/artboard-label/`BitmapNode` mip-cache convention. The "onion skin on by default / double-click to disable" note in the issue is stale (pre-3.8.0 animation-controls rework): defaults are now `false` and the toggle is single-click. **Follow-up (Track Q):** golden-image test comparing export with onion skin on/off — blocked on there being a test project.
- [x] Box-selection target movement interrupt — [#225](https://github.com/gritsenko/Pix2d/issues/225) (labeled Hot). Fixed by the transform-tool rewrite (`PixelTransformTool` / `SelectionController`): copy-on-write working-bitmap snapshots prevent tearing mid-transform (a638463), `MoveThumbNode` now raises a cancel event on interrupted drags (9dc8b41), and click-outside commits the transform instead of dropping it (4a5b18d) — a box-selection drag no longer disconnects partway through. **Follow-up (Track Q):** pointer-event regression test once a test project exists.
- [x] Pixel-perfect stroke flicker — [#241](https://github.com/gritsenko/Pix2d/issues/241). Resolved by the pixel-perfect drawing rework (swap-bitmap preview management `03b4282`, incremental preview + optimized bitmap handling `cf92167`, earlier `9e2e39f`); confirmed fixed in current builds.
- [x] Slider mouse-wheel support on desktop — [#242](https://github.com/gritsenko/Pix2d/issues/242) (small UX win, cheap). `SliderEx` now adjusts on `PointerWheelChanged` while hovered (one notch = 1 step, Ctrl = 10, clamped to min/max); the event is marked handled so a parent `ScrollViewer` doesn't scroll instead. Applies to all three internal slider layouts (two-line / one-line / narrow popup).
- [x] Palette slider interruption — [#236](https://github.com/gritsenko/Pix2d/issues/236). Not reproducible on desktop; hardened preventively: `Pix2dColorPicker` now marks its color-square / hue-slider pointer events `Handled` so a parent `ScrollViewer`'s touch `ScrollGestureRecognizer` can't hijack the pointer mid-drag and steal the capture (the capture-steal is what interrupted the drag on touch). Same class of fix as the slider mouse-wheel handling in [#242].
- [x] Grid toggle did nothing — enabling "Show grid" in the grid-settings flyout never showed the grid. `GridSettingsView.State` captured a single `ViewPortState` instance at construction; the flyout is built once with `MainView` (before the first real project is current, and stale after every tab switch), so toggles wrote to an orphaned `ViewPortState` that no watcher — `SnappingService`/`ViewPortRefreshService` both rebind via `WatchForCurrentProjectViewPort` — ever observed. Fixed by making the view resolve `AppState.CurrentProject.ViewPortState` **live** on every read/write and rebind through `WatchForCurrentProjectViewPort` (which also reflects the Ctrl+. `ToggleGrid` shortcut back into the switch) — the same stale-binding gotcha documented in `CLAUDE.md`. Verified end-to-end against a running Debug build via the AgentTools inspector (flyout switch toggle now drives the active project's grid node in both directions).
- [x] Narrow-screen (phone-portrait) dialogs/banners overflowed the viewport. On a ~290px window the telemetry-consent dialog (fixed `.Width(400)`), the unsaved-changes dialog (three fixed 100px buttons), and the crash-recovery banner (non-wrapping horizontal row) spilled off-screen. Fixed at two levels: (1) systemic — [`PopupView`](../Sources/Core/Pix2d.Core/UI/Shared/PopupView.cs) (the dialog host) now clamps its width to the viewport (`MaxWidth` + a restore-able `MinWidth` clamp) and re-fits on parent resize/rotation via a `Bounds` subscription bound in `ApplyPositionForCurrentLayout`; [`DialogContainer`](../Sources/Core/Pix2d.Core/UI/Shared/DialogContainer.cs) now starts `IsOpen(false)` so the *first* dialog shown (startup telemetry prompt) actually fires `OnOpened` and gets the clamp. (2) per-view — telemetry/unsaved dialogs use `MaxWidth` + stretched-column button rows (no fixed widths), text wraps; the recovery banner ([`MainView`](../Sources/Core/Pix2d.Core/UI/MainView.cs)) stretches with margins under a `MaxWidth(560)` cap with a wrapping text column. Also localized + wrapped the previously hardcoded unsaved-changes strings. Verified end-to-end via the AgentTools inspector (`set_window_size` 290→266px clamp, `layout_audit` clean, no overflow) for all three at phone-portrait width.
  - **Follow-up (done):** repositioned the crash-recovery banner from centre-screen to a top notification zone directly under the top toolbar (a Row-2 slot in the full-width top strip in [`MainView`](../Sources/Core/Pix2d.Core/UI/MainView.cs)); on a narrow screen its Dismiss button now wraps onto its own line. Re-enabled the previously commented-out **rate/review prompt** in the same zone and made it responsive — [`RatePromptView`](../Sources/Core/Pix2d.Core/UI/RatePromptView.cs) now uses the shared `notify-card`/`notify-content` styles (centred one-row on desktop, stretched + actions-stacked on narrow) and its `IReviewService` ctor arg defaults to null so it builds on desktop/web (where the prompt stays hidden) instead of throwing. Both banners share global `notify-card`/`notify-content` styles in [`AppStyles`](../Sources/Core/Pix2d.Core/UI/Styles/AppStyles.cs) (global so they also reach the nested `RatePromptView`). **Tool/action bars** ([`TopToolUiContainer`](../Sources/Core/Pix2d.Core/UI/TopToolUiContainer.cs), [`ActionsBarView`](../Sources/Core/Pix2d.Core/UI/ActionsBarView.cs)) — especially the wide selection-tool settings — now scroll horizontally instead of clipping off-screen: each is a horizontal `ScrollViewer` whose width is clamped to the window client size via [`ViewportSizeExtensions.ClampMaxWidthToViewport`](../Sources/Core/Pix2d.Core/UI/Shared/ViewportSizeExtensions.cs) (a plain `MaxWidth` or star column can't bound them here — the bottom side-panels contaminate the grid's Auto columns' width). Verified via AgentTools at 290/800/900px.
- [x] Ctrl+S on a PNG-backed project should overwrite the source image — [#200](https://github.com/gritsenko/Pix2d/issues/200) (Hot, `complexity:low`). When a project was opened from a flat `.png` and is still a single sprite / single layer / single frame, `ProjectService.SaveCurrentProjectAsync` now writes back to the original PNG (via the existing `IExportService.ExportNodesToFileAsync` render path) instead of popping a "Save as .pix2d" dialog. `ProjectState.File` already keeps the opened source reference, so no new tracking was needed; the extension match is case-insensitive. Adding a layer/frame/artboard changes the shape so it correctly falls through to the project save. Desktop-only (Android/WASM use `UseInternalFolder`). One-file change in [`ProjectService.cs`](../Sources/Core/Pix2d.Core/Services/Project/ProjectService.cs) (+ `IExportService` ctor dep). **Verified** (manual, desktop): editing a PNG-backed single-layer/frame project and pressing Ctrl+S overwrites the source image silently; adding a layer/frame falls back to the `.pix2d` Save As.
- [x] Palette doesn't highlight the picked color — [#220](https://github.com/gritsenko/Pix2d/issues/220) (Hot, `bug`, `complexity:low`). Root cause: the [`ColorPalette`](../Sources/Core/Pix2d.Core/UI/Shared/ColorPalette.cs) control had no concept of a "selected" swatch — every swatch drew the same fixed border, and nothing compared the current color to palette entries. Added a `SelectedColor` `DirectProperty` (the Markup.Declarative generator auto-emits the `.SelectedColor(...)` binding) that highlights the matching swatch (2px full-opacity white border) via an in-place restyle (no rebuild churn during HSV drag), and bound it to the existing `state.SelectedColor` — which already tracks the eyedropper pick through `SpriteEditorState.CurrentColor` — on both the Recent and Custom palettes in [`ColorPickerView.cs`](../Sources/Core/Pix2d.Core/UI/ColorPickerView.cs). **Verified end-to-end** via the AgentTools inspector: selecting a color highlighted the matching swatch in both palettes (2px white ring) while non-matching swatches kept the dim border.
- [x] Show the eyedropper cursor + toolbar highlight while Alt is held over a brush — [#184](https://github.com/gritsenko/Pix2d/issues/184) (`UX/UI`). Holding Alt over a brush-family tool (`PixelBrushToolBase`: Brush/Eraser/pixel Shape) makes it pick a color instead of draw, but there was no visible feedback until now. Added a transient `ToolsState.IsColorPickerModeActive` flag that [`SkiaCanvas`](../Sources/Core/Pix2d.Core/SkiaCanvas.cs) (owns key events + cursor) sets on Alt-down/clears on Alt-up (and on tool switch, so it can't stick), driving a picker cursor (`StandardCursorType.Cross`), and had [`ToolItemView`](../Sources/Core/Pix2d.Core/UI/ToolBar/ToolItemView.cs) OR the eyedropper's toolbar highlight on the same flag. Three small files, no new subsystem. *Note: Avalonia has no stock eyedropper cursor — `Cross` is the zero-asset approximation; a custom bitmap cursor from icon glyph `\xE91B` is a possible follow-up.* **Verified** (manual, desktop).
- [x] `ArgumentOutOfRangeException` in `LayersView.State.InvalidateThumbnailItems` — Sentry crash on 3.9.0 (Android, 19 events / 6 users). Root cause: the index-based overload did `Layers[ReverseIndex(index)]` where `ReverseIndex = Layers.Count - index - 1`. An operation's `AffectedLayerIndexes` are captured at operation time and can fall outside the UI's `Layers` mirror (operation targeting a different sprite/frame than the one displayed, a layer-count mismatch, or the mirror not yet reloaded on tab/artboard switch), producing a negative or too-large index that threw on the indexer — surfacing as an unobserved-task crash via `OnOperationInvoked`. Fixed by bounds-checking the reversed index in [`LayersView.cs`](../Sources/Core/Pix2d.Core/UI/Layers/LayersView.cs) and skipping out-of-range entries (matching the null-safe `FirstOrDefault` pattern of the sibling `Layer`-based overload); a skipped thumbnail refreshes on the next `ReloadLayers`, so it's cosmetically harmless.
- [x] `NotImplementedException` — Sentry crash on 3.9.0 (Android, "Arg_NotImplementedException", no frames). The most probable trigger: **Bake effect** (layer effects UI → `EffectsService.BakeEffect` → `BakeEffectOperation`) called [`EffectExtensions.ApplyToBitmap`](../Sources/Core/SkiaNodes/Extensions/EffectExtensions.cs), which unconditionally threw `NotImplementedException` — baking *any* layer effect crashed on every platform. Implemented it mirroring `SKNodeRenderer.RenderEffectsToSurface` (bitmap → surface, `effect.Render(rc, surface)`, pixels read back); verified for all three effect types (Replace/Back/Overlay: grayscale converts, shadow preserves content + offsets, outline renders). Also defused the other reachable NIE stubs: `AndroidPlatformStuffService.ToggleTopmostWindow`/`OpenAppDataFolder` and the browser `OpenAppDataFolder` are safe no-ops, and the `ClipboardCommands` General-context Copy/Paste/Cut placeholders (bound to global Ctrl+C/V/X) log a trace instead of throwing. Remaining NIE stubs (`BitmapNode.Clear`/`ModifyBitmap`/…, `SelectionService.SelectNext`, `EditContext.Title`) are verified-unreachable dead code. See the Track Q diagnostics entry for why the Sentry event was frame-less and how that's fixed.

### H1.2 Project file format hardening `P0`
- [x] Introduce explicit **format version** field in `.pix2d` files with a migration pipeline (`v(n) → v(n+1)` migrators, never in-place mutation of old files). Landed: a `manifest.json` entry (`{"formatVersion":N}`) is the version anchor; [`ProjectFormat`](../Sources/Core/Pix2d.Shared/Project/ProjectFormat.cs) is the single load path (used by both [`ProjectUnpacker`](../Sources/Core/Pix2d.Shared/Project/ProjectUnpacker.cs) and the autosave [`IncrementalSessionStore`](../Sources/Core/Pix2d.Core/Services/AutoSave/IncrementalSessionStore.cs)) and runs the [`ISceneJsonMigration`](../Sources/Core/Pix2d.Shared/Project/ISceneJsonMigration.cs) chain on the parsed JSON before deserializing. Files without a manifest are read as the baseline version. **Also hardened the biggest coupling point:** `$type` is now a *stable key* from [`NodeTypeRegistry`](../Sources/Core/SkiaNodes/Serialization/NodeTypeRegistry.cs) rather than the CLR full-name, so renaming/moving a node class no longer breaks old files; unknown types degrade gracefully (skip node) instead of throwing. First real migration shipped — [`UnwrapArtboardNodeMigration`](../Sources/Core/Pix2d.Shared/Project/Migrations/UnwrapArtboardNodeMigration.cs) (`v1 → v2`) flattens the removed `ArtboardNode` container that pre-3.x files nested around each sprite (those files failed to open before). `CurrentVersion = 2`.
- [x] Backward-compatibility test corpus. Implemented as a standalone console harness [`Sources/Tools/Pix2d.FormatTests`](../Sources/Tools/Pix2d.FormatTests) that loads every [`TestImages/`](../TestImages) `.pix2d` through the real unpacker and asserts structure **plus a save→reload round-trip** (stable-key serialization → reload → counts preserved). *Corrected two stale hints in this item:* the sample files live in `TestImages/` (not `TestSer/`, which is an unrelated scratch project), and the assertion is structural + round-trip, not golden-image render (that remains blocked on a real test project — Track Q). Current status: 34/34 loadable files pass; `ptvRightTemplate.pix2d` is flagged as a corrupt archive (broken ZIP central directory) and ignored. Harness is intentionally **not** in `Pix2d.slnx` so CI/solution build are unaffected.
- [x] **Serialization contract guard.** The harness also pins the per-type serialized property set in a checked-in [`format-contract.json`](../Sources/Tools/Pix2d.FormatTests/format-contract.json) and fails on drift, making the implicit "any property with a setter" contract explicit and enforced. It surfaced junk the heuristic was persisting — a `flushRequestedAction` delegate and the transient `isDirty` flag on nodes.
- [x] **Property pruning (two passes).** Removed non-document values from the format via `[JsonIgnore]`, all verified behaviour-preserving against the corpus (still 34/34): `SKNode.IsDirty` (transient render flag; its private setter was being serialized, and a saved `false` could skip a node's first paint), `BitmapNode.FlushRequestedAction` (runtime delegate), `SKNode.IsInteractive` (runtime hit-test flag — set only on adorner nodes, `false` in all 1402 corpus occurrences), and `NodeDesignerState.IsSelected`/`IsExpanded` (editor selection + tree-expansion UI). Kept genuine document state (`IsLocked`, `LockAspect`, `ShowChildrenInTree`, `ExportSettings`). No version bump — pruning is reader-tolerant both ways, so it only needs a contract-snapshot regen. The contract guard was extended to also cover inline value objects (`NodeDesignerState`/`NodeExportSettings`/`OnionSkinSettings`) so their fields are drift-protected too.
- [x] Crash-recovery: after an **unclean** shutdown, surface restored per-tab autosave to the user. Silent workspace restore (browser-style) was already shipped; added a non-blocking banner (inline in [`MainView`](../Sources/Core/Pix2d.Core/UI/MainView.cs), gated by `MainViewModel.ShowRecoveryNotice`) shown only when the previous run crashed/was killed, reusing `ICrashReportService.PreviousShutdownWasClean` (no new marker) to gate it. Autosave scene JSON is also format-versioned (`SessionManifest.sfv`) and migrated through the same pipeline. *Chose banner over a modal "restore?" prompt so it doesn't fight the deliberate always-restore UX.* Verified end-to-end (kill → banner for 3 tabs; graceful close → silent, no banner).
  - **Follow-up (resolved):** the banner no longer renders centre-screen — it now sits in a top notification zone directly under the top toolbar (Row 2 of the full-width top strip in `MainView`), diagnosed and verified with the AgentTools layout inspector (Track E.3). See the narrow-screen item under H1.1 for the details.
- [x] Document the format in [`docs/file-format.md`](file-format.md) — container layout, `project.json` node tree, stable `$type` key registry, versioning + how to add a migration, the contract guard, autosave + crash banner, and the corpus harness.

## 4. Horizon 2 — Closing the Game-Dev Loop (3–9 months)

Goal: features that convert "nice pixel editor" into "the tool my game pipeline depends on."

### H2.1 Tilemap / tileset mode `P1` — *flagship feature*
The single biggest gap vs. Aseprite's [tilemap mode](https://www.aseprite.org/docs/tilemap/) and the top reason game devs pick a tool.
- [ ] Tile drawing with **live wrap preview** (canvas rendered repeated 3×3 so seams are visible while drawing).
- [ ] Tileset panel: tiles as first-class reusable objects; painting a map by stamping tiles.
- [ ] Auto-tiling metadata (Wang tiles / blob tilesets — see [reference](https://web.archive.org/web/2024/http://www.cr31.co.uk/stagecast/wang/blob.html)).
- [ ] Export: tileset image + JSON metadata; target compatibility with [Tiled TMX/TSX](https://doc.mapeditor.org/en/stable/reference/tmx-map-format/), [Godot TileSet](https://docs.godotengine.org/en/stable/tutorials/2d/using_tilesets.html), and [Unity Tilemap](https://docs.unity3d.com/Manual/class-Tilemap.html).

### H2.2 Engine-ready export pipeline `P1`
Sliced into increments (architecture doc via Fable): **PR-1 sheet v2 + Aseprite JSON** (shipped) → **PR-2 CLI** (shipped) → PR-3 model metadata (tags/durations/pivot) → PR-4 engine presets → PR-5 ship CLI in the release pipeline. The model work is deliberately **not** a prerequisite: the JSON shape is fully emittable from today's model (uniform duration, empty `frameTags`/`slices`) and only gains richer values when PR-3 lands — a sheet exported now stays forward-compatible.
- [ ] **Sprite sheet export v2**: packing (grid + tight), per-tag animation ranges, frame durations, pivot points, 9-slice data. **Shipped (PR-1):** a pure sheet-export core in [`Pix2d.Shared/Export/Sheet`](../Sources/Core/Pix2d.Shared/Export/Sheet) — one intermediate [`PackedSheet`](../Sources/Core/Pix2d.Shared/Export/Sheet/SpriteSheetModels.cs) (one packing result → PNG + N metadata sidecars) built by [`SpriteSheetBuilder`](../Sources/Core/Pix2d.Shared/Export/Sheet/SpriteSheetBuilder.cs): renders every frame headlessly (CPU Skia), optional **trim** to opaque bounds ([`FrameTrimmer`](../Sources/Core/Pix2d.Shared/Export/Sheet/FrameTrimmer.cs)), **grid** ([`GridSheetPacker`](../Sources/Core/Pix2d.Shared/Export/Sheet/GridSheetPacker.cs)) or **tight** shelf packing ([`ShelfSheetPacker`](../Sources/Core/Pix2d.Shared/Export/Sheet/ShelfSheetPacker.cs)), configurable **spacing**, **power-of-two** sizing, per-frame placement + trim/source geometry. The in-app entry point is the new [`SpriteSheetExporter`](../Sources/Core/Pix2d.Core/Plugins/ImageFormats/PngFormat/Exporters/SpriteSheetExporter.cs) (Export dialog → **Sprite sheet (PNG + JSON)**, replacing the old grid-only `SpritesheetImageExporter`); it writes the sheet PNG + a metadata sidecar next to it (desktop) or via a second prompt (mobile/web). Also deleted the dead `Exporters/AtlasPacking/` scaffolding (`AtlasPacker`/`Spritesheet`/`TextureInfo`, never instantiated — repo-hygiene win, H1.3). **Remaining (PR-3):** the animation-metadata **model** — named tags (idle/run/jump), per-frame durations (ms), pivot + 9-slice on `Pix2dSprite` — which populates the (already-emitted) `frameTags` / real `duration` / `slices` fields, plus the timeline UI to author them (H2.4). Frame rotation in the packer is also deferred.
- [x] JSON metadata schema, documented in [`docs/export-format.md`](export-format.md). Structurally compatible with [Aseprite's `--data` JSON](https://www.aseprite.org/docs/cli/#data) (`frames` hash by default, `frame`/`rotated`/`trimmed`/`spriteSourceSize`/`sourceSize`/`duration`; `meta{app,version,image,format,size,scale (string),frameTags,layers,slices}`; optional Pixi-style `animations` map; `json-array` form available) so existing engine importers work out of the box. Emitted through a pluggable [`ISheetMetadataEmitter`](../Sources/Core/Pix2d.Shared/Export/Sheet/Metadata/ISheetMetadataEmitter.cs) ([`AsepriteJsonEmitter`](../Sources/Core/Pix2d.Shared/Export/Sheet/Metadata/AsepriteJsonEmitter.cs) + Newtonsoft DTOs) over the shared `PackedSheet`, so the engine presets below drop in as sibling emitters. Pivot + 9-slice map to `meta.slices` (Aseprite's own mechanism: `pivot` = anchor, `center` = 9-slice inner rect). **Verified** headlessly in [`Pix2d.ScenarioTests`](../Sources/Tools/Pix2d.ScenarioTests) (grid dims, trim shrink, JSON structure/durations/size — 8 new assertions, all green).
- [ ] Direct presets: [Godot SpriteFrames](https://docs.godotengine.org/en/stable/classes/class_spriteframes.html) `.tres`, Unity-friendly sheet + meta, [libGDX TexturePacker atlas](https://libgdx.com/wiki/tools/texture-packer) format. (PR-4 — new `ISheetMetadataEmitter`s over the same `PackedSheet`.)
- [x] **Headless CLI** — `pix2d export project.pix2d --spritesheet out.png --data out.json` runs (PR-2). Landed as [`Sources/Tools/Pix2d.Cli`](../Sources/Tools/Pix2d.Cli) (assembly `pix2d`), a console tool referencing **only `Pix2d.Shared`** — no Avalonia, no DI, no display — so it runs on a bare headless CI runner (the sheet engine renders on CPU Skia and `ProjectUnpacker` loads the `.pix2d` directly, the same primitive the app's `IProjectService` uses). It calls the **same** `SpriteSheetBuilder` + `AsepriteJsonEmitter` as the in-app exporter, so CLI and GUI output are identical. Verbs: `export` (`--spritesheet` req, `--data`, `--format`, `--sheet-type grid|tight`, `--columns`, `--padding`, `--trim`, `--pot`, `--scale`, `--artboard <name|idx>`), `list` (artboards/size/layers/frames/fps as pipeable JSON on stdout — load-time diagnostics go to stderr, so `pix2d list x.pix2d | jq` works), `--version`/`--help`. Exit codes 0/1/2 (ok / runtime error / bad args). Out of `Pix2d.slnx` (same policy as `Pix2d.FormatTests`/`Pix2d.ScenarioTests`); **verified** end-to-end against `TestImages/123frames.pix2d` (grid 192×64 + valid Aseprite JSON, tight+trim+pot+scale packs a valid sheet, `list` JSON validates). Also the foundation for the MCP server (Track E.3). **Next (PR-5):** promote into `release-publish.yml` as a published artifact; wire `--tag` once PR-3 lands the tag model.

- [x] **Export dialog: animation preview + output summary.** The Export dialog ([`ExportView`](../Sources/Core/Pix2d.Core/UI/Export/ExportView.cs)) now surfaces a **playback bar** for animated sprites (>1 frame) — play/pause · stop · prev/next · a frame-scrub `Slider` + `n/N` counter (reusing the `anim-btn` style + `Pix2dIconFontFamilyV3` glyphs from `AnimationControlsView`), driven by a dialog-local `DispatcherTimer` so it doesn't fight the editor's own playback timer. Scrubbing sets the sprite's current frame, so a **single-frame exporter (PNG/JPG/SVG) exports exactly the previewed frame** (with a "The selected frame will be exported" hint), while multi-frame exporters (GIF / sheet / PNG sequence) treat the bar as pure preview. Added a live **Output** summary — resolution + estimated file size, or `N files · ~total` for the sequence — computed from the *real* exporters (`IStreamExporter.ExportToStreamAsync` for PNG/JPG/GIF/sheet, dimensions decoded via `SKCodec`; per-frame PNG sum for the sequence; `SvgImageExporter.Export` for SVG), debounced 250 ms and refreshed on scale / selected-frame / packing-option changes (`SpriteSheetExportSettingsView` + `SpritePngSequenceExporterSettingsView` now raise a `SettingsChanged` event the dialog subscribes to). The **sprite-sheet preview shows the actual packed sheet** (decoded from the exporter's own output stream, normalised to `SKApp.ColorType` — `SKBitmap.Decode` returns platform-native BGRA on Windows, which `ToBitmap`'s fixed Rgba interpretation would otherwise show with swapped R/B). The preview has a **fit/zoom overlay** mirroring `ZoomPanelView` (− / Fit / +): the `SKImageView` is sized to *source px × zoom* inside a `ScrollViewer` (pans when zoomed past the pane), **Fit** recomputes to fill the pane uniformly on every pane/image resize, and nearest-neighbour interpolation (opt-in `SKImageView.PixelPerfect`) keeps pixels crisp. Action buttons now sit in a **dedicated bottom grid row** (`*,*,Auto`) rather than floating `VerticalAlignment.Bottom`, so on short screens they no longer overlap the settings and the settings `ScrollViewer` scrolls its full content. Also added a seam-free transparency checker (`StaticResources.Brushes.CheckerBrush` — a vector 2×2 `DrawingBrush` tiled on integer boundaries) replacing the old `CheckerTilesBrush` (image + `Stretch=Uniform` + `ScaleTransform`, which showed gaps in non-square boxes) for `SKImageView` previews. en + ru localized. **Next:** animate the GIF/sequence preview (loop playback) the same way the sheet now shows the packed result.

### H2.3 Interop: import competitors' formats `P1`
- [ ] `.ase`/`.aseprite` import — full spec is public: [ase-file-specs.md](https://github.com/aseprite/aseprite/blob/main/docs/ase-file-specs.md). Start read-only (layers, frames, tags, palette); write support is `P3`.
- [x] Palette import/export + **named-palette library**: [GIMP `.gpl`](https://developer.gimp.org/core/standards/gpl/), plain `.hex`/`.txt`, PNG swatch strip, and direct fetch from [Lospec](https://lospec.com/palettes/api) (accepts a slug or a full palette URL). Format codecs are pure/no-IO in [`PaletteFormats`](../Sources/Core/Pix2d.Core/Services/Palette/PaletteFormats.cs) (GPL parse/write, tolerant hex-list parse/write, PNG grid render + distinct-color scan, Lospec JSON parse) and selected by the chosen file extension. Import replaces the live Custom palette **and** stores it in the library so it's reloadable; export writes the current Custom palette (`.gpl` default — the most portable; type `.hex`/`.png` to switch). The library is a `List<PaletteData>` persisted via a new `AppSettings.SavedPalettes` property (the reflection-based [`SettingsService`](../Sources/Core/Pix2d.Core/Services/SettingsService.cs) only round-trips keys that exist as `AppSettings` properties — arbitrary keys silently no-op). `IPaletteService`/[`PaletteService`](../Sources/Core/Pix2d.Core/Services/PaletteService.cs) gained `SetPaletteColors` + `Save/Load/DeleteSavedPalette` + the three `*Async` IO methods (now `// Depends on: ISettingsService, IFileService`). UI lives in the color-picker ([`ColorPickerView`](../Sources/Core/Pix2d.Core/UI/ColorPickerView.cs)): everything hangs off **one compact `⋯` menu button** in the top-right of the tab strip, whose `MenuFlyout` holds Load palette ▸ (submenu of saved palettes, load-on-click), Save current…, Delete saved palette ▸ (submenu), Import…, Export…, Load from Lospec… — name/slug prompts via `IDialogService`. Saved lists are **submenus** (arbitrary length never overflows) and the flyout opens downward from a top-anchored button (no bottom clip — the earlier `ComboBox`/bottom-bar layout clipped its dropdown). Localized (en + ru). **Remaining:** a format dropdown in the save dialog (the shared `GetFileToSaveWithDialogAsync` groups all extensions into one filter, so non-`.gpl` export needs a typed extension) and `.ase` palette import (folded into the `.ase` importer work below).
- [ ] `.piskel` import (JSON-based, trivial) — free user migration from Piskel.

### H2.4 Animation to competitive parity `P2`
- [ ] Animation **tags/ranges** within one document (idle / run / jump), exported as ranges in metadata.
- [ ] Per-frame duration (ms), not just global FPS.
- [ ] Linked cels (share one image across frames) — memory + workflow win for static parts.
- [ ] Export animated **GIF** — quality fixed: the encoder ([`AnimatedGifEncoder`](../Sources/Core/Pix2d.Core/Plugins/ImageFormats/GifFormat/Exporters/Gif/AnimatedGifEncoder.cs)) previously ran the `NeuQuant` quantizer **per frame** and wrote a **local color table per frame**, so identical colors drifted frame-to-frame and pixel-art shades flickered. It now builds **one palette shared by the whole animation** (Global Color Table, no local tables): if the animation fits the palette budget its colors are used **verbatim** (no quantization — exact fidelity), otherwise a single NeuQuant pass over all frames combined produces one shared reduced palette; transparency slot reserved only when actually used. Verified end-to-end (structural: 0 local color tables in all paths; round-trip: SkiaSharp `SKCodec` decodes every frame byte-exact). **Remaining:** **APNG** export and sprite-sheet-per-tag.

### H2.5 Scripting v1 (pre-plugin) `P2`
Cheaper to ship and maintain than a full plugin API; lets the community close niche gaps themselves.
- [ ] Embed a scripting runtime — candidates: Lua via [MoonSharp](https://github.com/moonsharp-devs/moonsharp) / [Lua-CSharp](https://github.com/nuskey8/Lua-CSharp), or C# scripting via [Roslyn Scripting API](https://github.com/dotnet/roslyn/blob/main/docs/wiki/Scripting-API-Samples.md). Decision doc first (`.plans/`).
- [ ] Minimal stable API surface: document, layers, frames, pixels, palette, selection, export. Version it from day one.
- [ ] Batch-run scripts from CLI (`pix2d run script.lua project.pix2d`) — synergy with H2.2.

## 6. Track E — AI & Agent Integration (continuous, starts in Horizon 2)

Philosophy: **"AI drafts, human finishes, agent ships."** Never "AI draws instead of you."

### E.1 Generation as a draft layer `P2`
- [ ] "Generate to artboard": call an image provider (user-supplied API key; providers behind an interface — OpenAI Images, Stability, local [ComfyUI](https://github.com/comfyanonymous/ComfyUI) endpoint, etc.) and place the result as a normal layer.
- [ ] **Killer step — pixelization/quantization pass**: snap any generated/imported image to the project's palette and pixel grid. Pure generators do this badly; Pix2D already owns palettes. Algorithms: nearest-in-palette with optional [ordered dithering](https://en.wikipedia.org/wiki/Ordered_dithering) (Bayer), k-means palette extraction for "adopt palette from image".
- [ ] Ship the quantization pass as a standalone tool too (works without any AI provider) — immediately useful for reference images.

### E.2 AI-assisted grunt work `P3`
- [ ] Animation inbetweening between two keyframes (start with classical morphing/optical-flow approaches before ML).
- [ ] Palette-swap / recolor suggestions; tile variation generation.
- [ ] Style-preserving scale (integrate/reference [xBRZ](https://sourceforge.net/projects/xbrz/) or similar for upscale; content-aware downscale research).

### E.3 MCP server + agent-facing CLI `P1 within this track` — *strategic*
Make Pix2D drivable by AI agents so it becomes a node in AI game-dev pipelines.
- [ ] Build on the headless CLI (H2.2). Implement an [MCP](https://modelcontextprotocol.io/) server ([spec](https://spec.modelcontextprotocol.io/), [C# SDK](https://github.com/modelcontextprotocol/csharp-sdk)) exposing tools such as:
  - `open_project(path)` / `get_project_info`
  - `export_spritesheet(project, tag?, format)` / `export_tileset`
  - `apply_palette(project, palette_source)`
  - `quantize_image(input, palette, grid)` (from E.1)
  - `run_script(project, script)` (from H2.5)
- [ ] Publish to MCP registries; document an end-to-end demo: *"agent generates art → quantizes in Pix2D → exports Godot SpriteFrames → game builds in CI."* That demo is also marketing (Track C).
- [ ] Keep `CLAUDE.md` and `.claude/skills/pix2d-ui` current — the repo itself must stay agent-friendly, since agent-assisted velocity is the project's core competitive advantage.
- [ ] **Improve the in-process `Declarative.Avalonia.AgentTools` inspector for layout debugging.** Today it exposes `get_visual_tree` / `list_components` / `screenshot_control` / `get_errors` but no *layout* info, so an agent debugging a view that "doesn't show" is reduced to blind screenshot-diffing. Add a `get_layout(selector)` (per-control `Bounds`, `DesiredSize`, `IsVisible` chain, effective `HorizontalAlignment`/`VerticalAlignment`) — or enrich `get_visual_tree` with those fields — plus a `highlight(selector)` overlay. This turns "why is this element invisible?" from ~15 screenshot iterations into one query. *(Motivating case: the crash-recovery banner below — a zero-size / non-rendering `VerticalAlignment.Bottom` child would have been obvious instantly.)*

- [ ] **Upgrade GitHub Actions off Node.js 20** `P3` — the v3.9.0 release run warned that `actions/checkout@v4`, `actions/setup-dotnet@v4`, `actions/upload-artifact@v4`, `actions/download-artifact@v4`, and `softprops/action-gh-release@v1` still target Node 20, which runners now force onto Node 24 and will [drop entirely](https://github.blog/changelog/2025-09-19-deprecation-of-node-20-on-github-actions-runners/). WASM still local-report-only (no reliable Sentry .NET browser-wasm support). **Session tracking now enabled** (`AutoSessionTracking = true` on both sinks) so Sentry receives release-health session envelopes (duration / error count / crash-free rate); with `IsGlobalModeEnabled` the SDK ends the session on `SentrySdk.Close()`. Android has no graceful process exit, so the double-back exit path (`BackPress` → `MainActivity.CloseTelemetrySinkSafely()`) closes the sink to flush a clean session end; desktop relies on the SDK's own ProcessExit hook. **Crash-event diagnosability (post-3.9.0, motivated by a frame-less "Arg_NotImplementedException" event):** (1) Android release builds set `UseSystemResourceKeys=false` so trimmed builds report real exception messages, not resource keys; (2) both sinks attach `stack_trace_text` / `exception_chain` / `session_op_log_tail` extras and mark fatals `SentryLevel.Fatal`, so even when SDK frame extraction yields nothing on AOT builds the event still carries the managed stack and the user's last operations; (3) a **non-fatal channel** (`ICrashReportService.CaptureHandled` → `ICrashTelemetrySink.CaptureNonFatal`, consent-gated, per-signature rate-limited) reports handled errors with an `error_source` tag; (4) `CommandService` no longer discards faulted command tasks (previously they surfaced only at GC time as context-free `UnobservedTaskException`s) — every shortcut/UI command execution is awaited and failures are logged + captured as `Command:<name>`.

Only `Logger.LogEventWithParams` events are forwarded — crashes/diagnostic logs are filtered out by `ILoggerTarget.EventsOnly`. Uses a random anonymous `AppSettings.InstallId`. WASM delivery requires the stats server to allow CORS from the app origin. Events emitted so far: `App launched` (with head `Platform`, fired once analytics is enabled), `Project created` (in `ProjectService.CreateNewProjectAsync`, with `Size` — covers File→New, Ctrl+T new tab, custom-size dialog), `Exporting image` (in `ExportView.Export`, with `Exporter`). **Unreachable-backend resilience**: the client skips flushes entirely while the OS reports no connectivity (`NetworkInterface.GetIsNetworkAvailable`, assumed online on WASM), uses a 15 s HTTP timeout (was the 100 s default — a blackholed host no longer pins a flush), drops a batch on 4xx (poison payload) while requeueing on 5xx/network errors, and after 5 consecutive failed flushes goes dormant for the rest of the process lifetime (queue dropped, `Track()` no-op). - [x] Unified telemetry consent (strict opt-in): a single `TelemetryConsent` (was crash-only `CrashTelemetryConsent`; legacy value migrated) now gates **both** analytics AND crash reporting. The first-launch consent prompt covers **Android + desktop + WASM** (the prompt has no crash-sink dependency; WASM keeps crash reports manual-only but browser analytics is opt-in-enabled), so no platform silently loses analytics under the opt-in model. **Hotfix (3.8.1):** the consent dialog crashed at Android startup on windowed/resizable devices (ChromeOS) — a config-change rebuild of `MainView` replaced the `DialogContainer` while a dialog view was still parented in the old one, throwing "already has a visual parent ContentPresenter". `AvaloniaDialogService.SetDialogContainer` now drops the stale current/queued dialogs on container replacement, and `DialogContainer.ShowDialog` detaches a view from any prior parent before re-hosting it.
